## 配置表生成和使用机制

### 策划侧（Excel → txt）
1. 策划在 Excel 中编辑配置数据
2. 运行配置表导出工具（TableTool.exe）
3. 生成 .txt 文件到 `table/default_ios/` 目录

### 服务端侧（txt → 内存结构）
1. 服务器启动时读取 .txt 文件
2. 按本表实际入口解析：静态文件用 READ_FILE；旧活动文件同步核查 READ_SYNC_FILE；数据库配置/独立业务协议核查各自登记与发送链，不统一替换加载宏
3. 加载到内存结构体（std::map）
4. 通过查询函数访问配置

### 客户端侧（txt → 自动生成代码）
1. Unity 编辑器读取 .txt 文件
2. 自动生成 TDXXXTable.cs 类
3. 生成 TableConfig.cs 注册代码
4. 客户端通过生成的类访问配置数据

**注册说明**:
- 文件位置：`Assets/Script/Table/TableConfig.cs`
- 注册方式：在 `delayLoadTableArray` 数组中添加 `TDXXXTable.metaData`

## 配置表定义

### {配置表1} - `{table_name}.xlsx`

**表文件路径**: 相对路径 `../design/table/default_ios/{table_name}.xlsx`
**状态**: ⚠️ 新增配置表 / 扩展现有表 / 部分字段由代码固定

**字段定义**:

| 字段名 | 类型 | 属性 | 说明 | 示例值 | 必填/可选 | 客户端使用 | 服务器使用 | 状态 |
|--------|------|------|------|--------|-----------|-----------|-----------|------|
| ActiveId | int | A | 活动ID，唯一标识 | 1001 | 是 | 是 | 是 | 新增 |
| Name | string | C | 活动名称，仅客户端UI展示 | "成长基金" | 是 | 是 | 否 | 新增 |
| RewardList | string | S | 奖励列表，仅服务端发奖逻辑使用 | "1:2:3" | 是 | 否 | 是 | 新增 |

**属性列说明（强制，不允许留空或"待定"）**：
- **S（Server）**：仅服务端使用，客户端不加载/不解析（服务端内部计算、权限校验字段）
- **C（Client）**：仅客户端使用，服务端不加载/不解析（客户端UI展示用的本地化key、特效ID、排序权重）
- **A（All）**：双端都使用，必须在服务端和客户端配置结构体中都定义（活动ID、奖励内容、条件阈值）

**判断依据**（不能用"客户端使用"列代替，那一列问的是"客户端业务逻辑要不要这个值"，S/C/A 问的是"客户端是否要通过本地生成的 TDXXXTable.cs 加载获得这个值"——两者可能相反：客户端逻辑需要该值，但值是通过协议动态下发而非本地配置表加载的，此时仍为 S）：
- 字段出现在服务端 `READ_FILE` 加载的结构体中 → 含 S 或 A
- 字段出现在客户端生成的 `TDXXXTable.cs` 类中 → 含 C 或 A
- 字段仅用于服务端业务逻辑 → S；仅用于客户端 UI 展示 → C；双端协议通信或共同业务逻辑 → A

**枚举值**（如果有枚举类型字段）:
```
DisplayType:
  1 = 自然时间
  2 = 永久
```

---------|-----------|------------
1001     | 成长基金   | 1:2:3:4
1002     | 进阶基金   | 5:6:7:8

### 客户端代码生成配置（强制）

**outcode_config.json 配置建议**（配置文件位置：`..\develop\client\tools\table\table_config\outcode_config.json`）

**1. need_copy 配置**（判断依据：字段定义表的"属性"列）
- 存在任何 C 或 A 字段 → 需要添加到 `need_copy`
- 全部为 S 字段 → 不需要添加

**本配置表结论**：
- [ ] 需要添加到 `need_copy`（包含 C 或 A 字段）
- [ ] 不需要添加（纯 S 字段，客户端完全不读取）

**2. NeedParseDataMethod 配置**（判断依据：配置加载方式）

> SE 专有生成规则：先读 `schemas/lr-func-dev/rules/common/se-config-generation.md`；`need_copy` 与 `NeedParseDataMethod` 分开判断，S 字段动态解析走工具临时转换，源表必须恢复。
- 配置加载方式：[ ] 静态配置（打包时加载，运行时不变） / [ ] 动态配置（服务端运营期间可调整，通过协议推送到客户端）
- 需要添加：客户端使用生成表类进行运行时动态解析（活动或非活动系统均按此判断）
- 不需要添加：纯静态加载，或数据仅通过独立业务协议传递且不用生成表类动态解析；不得按纯 C 或非活动直接豁免

**本配置表结论**：
- [ ] 需要添加到 `NeedParseDataMethod`（需要客户端表类动态解析）
- [ ] 不需要添加（仅静态加载，或独立业务协议下发且不用生成表类动态解析；注明证据）

**3. 实际同步入口与接入结论**（动态配置必填；静态配置注明不适用）

- 入口：旧活动文件拉取 / 数据库配置同步 / 独立业务协议（多入口分表说明）
- SE 源码依据：[服务端登记/发送入口；客户端请求/回包/解析入口]
- 旧活动文件拉取：核对 READ_SYNC_FILE/等价文件注册、表级适配与活动级注册；其他入口不强制套用这些活动链要求
- 数据库配置同步：核对实际登记、首次 Ready 请求、版本计划和回包解析、表级适配；不强制 READ_SYNC_FILE 或 IConfigSyncMethod
- 独立业务协议：核对字段、发送时机、接收与消费路径；NeedParseDataMethod 另按是否使用生成表类动态解析判断

## 对齐要求

- **字段顺序**: 客户端和服务器读取的列顺序必须一致

- **枚举值**: 客户端和服务器的枚举定义必须完全一致
