# lr-feishu：飞书策划案整理

## 这个技能做什么

把一份飞书策划案整理成**设计流程视角**的分章文档，供后续原型/评审使用。

- 下载飞书 wiki / docx 文档（或读取本地 Markdown）。
- 按固定顺序拆成 01~07 分章文件。
- 删除对原型无用的内容：美术资源、音频、配置表、埋点、服务端实现、世界观、版本规划、设计目标。
- 保留设计逻辑、页面与 UI、影响界面的待确认项。
- 不做完整性审查、不生成原型、不回写飞书。

## 输入

两种方式二选一：

```bash
# 飞书链接
python scripts/workflow.py --url "https://xxx.feishu.cn/wiki/xxx" --out "D:\path\out"

# 本地 Markdown（比如已经下载好的 working.md）
python scripts/workflow.py --input "D:\path\working.md" --out "D:\path\out" --images "D:\path\images"
```

凭据：优先读本技能根目录的 `config.json`；没有则复用 `../lr-design/config.json`。首次使用可从 `config.json.example` 复制填写。

## 输出

```
<out>/
├── README.md
├── 01-定位与核心循环.md
├── 02-系统规则.md
├── 03-次数与经济.md
├── 04-页面与UI.md
├── 05-待确认问题.md
├── 06-名词表.md
├── 07-流程图.md
├── 99-其他.md          # 仅当有未归类但保留的章节
└── images/
```

如果某类内容不存在，对应文件不会生成。

## 整理顺序

| 输出 | 内容 | 来源 |
| --- | --- | --- |
| 01 | 玩法定位、核心循环、双排名、复用约束 | 项目概述章 |
| 02 | 名次、积分、对手、刷新、防守、战斗 | 系统/玩法章的前半 |
| 03 | 挑战次数、结算、奖励、竞技币、战报、排行榜、异常 | 系统/玩法章的后半 |
| 04 | 界面清单、布局、交互原则 | UI/页面章 |
| 05 | 影响界面的待确认项 | 附录 A |
| 06 | 名词表 | 附录 B |
| 07 | 流程图 | 附录 C |

## 删除规则

默认保守：只有明确命中规则的章节/小节/表格行才删除，未命中一律保留。

- 整章：美术资源、音乐音效、策划配置表。
- 小节：设计目标、世界观、版本规划、AI 对接、对手数据来源、服务端数据结构、既有表改造、埋点。
- 表格行：服务端并发/跨周期/名次池等实现细节；防守快照的存储细节；既有系统关系只保留 UI 复用约束。

规则在 `scripts/filter_rules.py`，调整规则只改这个文件。详见 `references/filter-rules.md`。

## 使用要求

- 不要修改飞书源文档。
- 不要用本技能生成 proposal、specs 或 React 原型；它只负责整理输入。
- 如果输出目录已有同名文件，会覆盖同名章节；不会删除目录里的其他文件。建议每次用一个干净的输出目录，或复用同一个目录让章节保持最新。
- 图片只复制被分章文档引用到的；链接保持 `images/<文件名>` 相对路径。

## 验证

先跑本地样例，确认过滤和分章符合预期：

```bash
python scripts/workflow.py --input evals/fixtures/sample.md --out C:\tmp\lr-feishu-sample
```

检查输出中不存在美术/音频/配置表章节，且 01~07 文件齐全。

再用真实飞书文档跑一次，检查：

- README 的阅读顺序正确；
- 01~07 内容完整；
- 图片链接可达；
- 被删除的章节没有残留。
