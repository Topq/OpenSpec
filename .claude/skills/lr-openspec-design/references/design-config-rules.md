# design-config.md 生成规则

> **说明**: 本文档定义 design-config.md 的生成规则。
> 该文档从 proposal.md 和 specs/*.md 生成，用于策划和技术联合评审配置表设计。
> 
> **重要**: design-config.md 是技术评审的必要输入，用于对齐配置表结构、字段和使用方式。
> **策划权限约束**: 策划只有配置表权限，无前后端程序代码权限。所有涉及代码的决策必须联合前后端工程师。

## 配置表生成和使用机制

### 策划侧流程
1. 策划在相对路径 `../design/table/default_ios` 编辑 Excel 配置表
2. Excel 保存后自动导出为 txt 文件

### 服务器侧流程
1. 服务器直接读取 txt 文件
2. 运行时通过自定义解析代码解析为 C++ 结构体
3. 加载到内存 (std::map)

**自定义解析方式说明**:
- 在 `Init()` 中设置配置文件路径（使用 `util_set_path_value`）
- 在 `LoadResource()` 中调用加载函数
- 使用 `READ_FILE` 宏读取 txt 文件
- 使用 `txt.ReadInt(i, "FieldName")` 按字段名读取（字段名必须与 Excel 列名完全一致）
- 使用 `LogicAssert` 检查主键不重复
- 使用 `std::map` 存储配置，主键作为 key

**设计决策**:
- 为什么：自定义解析提供最大灵活性，支持复杂字段格式
- 字段名匹配：必须与 Excel 列名完全一致（大小写敏感）
- 备选方案：自动生成解析代码
- 为什么不选：现有项目使用自定义解析，保持一致性

### 客户端侧流程
1. 配置表 txt 更新后
2. 运行相对路径 `../develop/client/tools/table/output_code_csharp.bat`
3. 自动生成 C# 解析结构类 (TDXXXTable.cs)
4. **在 `TableConfig.cs` 中注册新表** (重要！)
5. 客户端通过生成的类访问配置数据

**注册说明**:
- 文件位置：`Assets/Script/Table/TableConfig.cs`
- 注册方式：在 `delayLoadTableArray` 数组中添加 `TDXXXTable.metaData`

**设计决策**:
- 为什么：自动生成代码减少手工编写错误
- 注册机制：延迟加载，减少启动时内存占用
- 备选方案：运行时动态加载
- 为什么不选：增加运行时开销，且难以类型检查

### 对齐要求
- **字段顺序**: 客户端和服务器读取的列顺序必须一致
- **数据类型**: int/string/float 必须对齐
- **必填/可选**: 服务器和客户端的空值处理必须一致

### 客户端访问方式

**生成的解析类**: `TDActive_growthfund_mainTable.cs`

**访问方式说明**:
- 单条查询：使用 `TDXXXTable.GetData(key)` 方法
- 遍历所有：使用 `TDXXXTable.GetAllData()` 方法
- 返回值：配置对象，包含所有字段属性

**设计决策**:
- 为什么：类型安全的访问方式，编译期检查
- 备选方案：字典查询
- 为什么不选：失去类型安全，容易拼写错误

### 服务器访问方式

**配置结构体**: 
- 定义位置：`{XXX}Module.h`
- 命名规范：`ST{ConfigName}`
- 成员变量：对应配置表字段

**访问方式说明**:
- 使用 `Get{Config}(key)` 方法查询
- 返回值：配置结构体指针（const）
- 空值处理：返回 NULL 表示配置不存在

**设计决策**:
- 为什么：使用 std::map 存储，O(log n) 查询效率
- 空值处理：返回 NULL 而非抛异常，调用方自行处理
- 备选方案：返回 Optional
- 为什么不选：C++ 标准库版本限制

## 配置表对齐检查

### 字段对齐检查

| 检查项 | 客户端 | 服务器 | 说明 |
|--------|--------|--------|------|
| 字段顺序 | 按 Excel 列顺序 | 按 txt 列顺序 | 必须完全一致 |
| 数据类型 | C# 类型 | C++ 类型 | int↔int, string↔fast_string, float↔float |
| 空值处理 | 默认值或null | 空字符串或0 | 必填字段不允许为空 |

### 使用对齐检查

| 字段 | 客户端 | 服务器 | 对齐状态 |
|------|--------|--------|----------|
| ActiveId | 用于查询配置 | 用于查询配置 | ✅ 对齐 |
| Name | UI显示 | 不使用 | ✅ 对齐（仅客户端） |
| FreeReward | 不使用 | 奖励发放 | ✅ 对齐（仅服务器） |
| ConditionType | UI显示条件类型 | 判定条件达成 | ✅ 对齐（双端使用，含义一致） |

**不对齐风险**:
- 字段顺序不一致 → 读取错位，数据错乱
- 类型不一致 → 解析失败或数据截断
- 含义不一致 → 客户端显示与服务器判定不符

## 配置表新增/修改流程

### 新增配置表

1. **策划侧**:
   - 在相对路径 `../design/table/default_ios` 创建 Excel 文件
   - 定义表头（字段名、类型、说明）
   - 填写示例数据

2. **客户端侧**:
   - 运行 `output_code_csharp.bat` 生成解析类
   - 在 `TableConfig.cs` 中注册新表
   - 在模块中通过 `TDXXXTable.GetData()` 访问

3. **服务器侧**:
   - 在 `{XXX}Module.h` 中定义配置结构体
   - 实现 `LoadXXXCfg()` 解析函数
   - 在 `Init()` 中调用加载

### 修改配置表字段

1. **策划侧**:
   - 修改 Excel 表结构（新增/删除/修改列）
   - 更新现有数据

2. **客户端侧**:
   - 重新运行 `output_code_csharp.bat`
   - 检查生成的类是否正确
   - 修改引用该字段的代码

3. **服务器侧**:
   - 修改配置结构体定义
   - 修改加载函数（按新列顺序解析）
   - 修改引用该字段的业务逻辑

4. **联合测试**:
   - 验证客户端显示正确
   - 验证服务器判定正确
   - 验证字段对齐（通过实际功能测试）

## Open Questions

> **Open Questions 明确规则**: 
> 
> **必须出现的问题类型**:
> 1. **配置表新增决策**: 设计阶段发现需要新增配置表或字段，但 proposal 未提及
> 2. **字段格式未确定**: 字段的具体格式、取值范围或命名规范未明确
> 3. **配置表关联**: 需要关联其他配置表但关联方式或字段未确定
> 4. **默认值和边界**: 字段的默认值、最大值、空值处理等边界条件
> 5. **配置表使用方式**: 客户端/服务器的读取方式、缓存策略等
> 6. **运营和策划流程**: 配置表的填写规范、审核流程等
> 
> **不应出现的问题**:
> - 已在 proposal 或 specs 中明确定义的内容
> - 纯技术实现细节（这应该在 design 中直接决定）
> - 过于宽泛的问题（"这个功能怎么做"）

### 配置表新增决策

1. **是否需要新建 `active_growthfund_main.xlsx`？**
   - 当前设计: 成长基金需要独立配置表
   - 问题: 能否复用现有 `business_activity_main.xlsx` 并扩展字段？
   - 影响: 策划新建配置表工作量、客户端/服务器解析逻辑
   - 建议: 新建独立表，因为字段差异较大且复用会增加复杂度

### 配置表结构

2. **`FreeHighlight` 和 `PayHighlight` 字段格式？**
   - 当前定义: 单个 itemID
   - 问题: 如果需要高亮多个奖励项，格式是 "id1;id2" 还是只允许单个？
   - 影响: 客户端 UI 高亮逻辑、配置表字段定义

3. **条件类型枚举是否需要扩展？**
   - 当前定义: 1=等级, 2=爬塔, 3=累计登录
   - 问题: 是否需要支持 4=累计充值, 5=完成指定任务？
   - 影响: 配置表枚举说明、服务器判定逻辑

### 配置表关联

4. **`RewardList` 字段是否必需？**
   - 当前设计: 存储奖励ID列表，与奖励表关联
   - 问题: 能否直接从奖励表查询该活动的所有奖励？
   - 影响: 配置表字段、查询逻辑

5. **时间配置 `PeriodName` 的命名规范？**
   - 当前示例: "growth_fund_202607"
   - 问题: 命名规则是什么？是否包含版本号？
   - 影响: 配置表填写规范、运营排期

### 默认值和边界

6. **`SortOrder` 默认值？**
   - 问题: 如果不填，默认排序是多少？是否允许重复？
   - 影响: 客户端排序逻辑、配置表填写规范

7. **奖励字符串的最大长度？**
   - 问题: `FreeReward` 和 `PayReward` 字段能支持多少个奖励项？
   - 影响: 字段类型（string vs text）、解析性能

### 字段补充决策

8. **是否需要补充 `business_activity_maintimelist.xlsx` 的 `ShowRemainTime` 字段？**
   - 当前设计: proposal 只说"显示倒计时"，未明确字段

   - 影响: 客户端 UI 倒计时逻辑、时间配置表结构
